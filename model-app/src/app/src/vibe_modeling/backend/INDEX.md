# Backend index

FastAPI app under `src/app/src/vibe_modeling/backend/`. One line per file/dir; keep current-state only when adding/moving/removing.

## Entry + routing

- `app.py` — FastAPI entrypoint, lifespan bootstrap, tracker startup.
- `router.py` — Primary run routes (POST /runs, validate, cancel, /runs/:id, /operations/:id, /agent-config, /progress, /health); at launch composes selected VibeInputs into the dispatched instructions via `compile_inputs` and writes the intended `RunInputLink` rows.
- `routes/businesses.py` — Business CRUD + import.
- `routes/versions.py` — Model-version reads, delete-with-reinstall, per-version artifact endpoints (business-scoped), installation drift probe + reconcile.
- `routes/config.py` — Agent configuration GET/PUT (notebook path + max_concurrent_runs).
- `routes/vibe_inputs.py`  -  Vibe Inputs CRUD (create accepts an optional `origin_context` resolved server-side to an anchor via `core/anchor_resolve.py`) + filters, run-selection (`setVibeInputSelection` bulk toggle of `selected_for_run`), consume/unconsume (re-link to head), context-link add/list, carry-forward, resumable re-link review queue (accept/reanchor/dismiss), the product-canonical review-state write surface (`markProductReview`/`clearProductReview` leaf marks + `markDomainReview`/`markSubdomainReview` cascade fan-out onto product rows; ADR D-044), read-only compile endpoint.
- `routes/deployment.py` — Deployment health surface.
- `routes/industries.py` — Industry catalog read.
- `routes/industry_models.py` — Industry *model* lifecycle (`/api/industry-models/*`, Wave 2): download / materialize / conflict / kickstart / publish for `kind='industry'` models. Distinct from `industries.py` (reference-table CRUD). Health route + `POST /download` (synchronous GitHub model download/materialize; conflict unit is the model SCOPE within the industry — creates the industry, adds a never-seen scope additively, or 409 `industry_model_already_exists` on a same-scope clash) + `publishModelVersion` (POST `/businesses/{id}/model-versions/{id}/publish`, OBO + ModelerOnly, co-located `PublishModelVersionOut`, delegates to `services/github_publish.py`) + `POST /{id}/kickstart` (`kickstartFromIndustry`, whole-model only, co-located `KickstartIn`/`KickstartOut`, delegates to `services/industry_kickstart.py`); further lifecycle endpoints appended by later Wave 2 tracks.
- `routes/import_root.py` — Industry-seed reference imports + bulk imports.
- `routes/platform.py` — Platform info (warehouses, catalogs, schemas).
- `routes/uc_browse.py` — Unity Catalog browser (`GET /api/uc/volumes/browse`) for the New Run form, plus `GET /api/uc/catalogs/{catalog}/schema-warning` that counts non-protected schemas so the form can warn before the agent drops them.
- `routes/sources.py` - Source-explorer read-only browse (`/api/sources/*`, Wave 1 Track C): capabilities + sectors → industries → models + a preview (folder-derived `scope`/`version`, rendered README, best-effort domain statistics parsed from the model's release notes - never fetches model.json), backed by the `sources/` connector resolved from `agent_config` GitHub pointers.
- `routes/_helpers.py` - Shared route helpers (`get_run_in_business`, `get_model_version_in_business`, `params_json_omit_deployment_catalog_for_multi_catalog`, validators). Delete surface: `delete_model_version` (rides DB cascades then runs the run GC), `gc_runs_for_deleted_version` (Philosophy B scalar-COUNT survivor check), `AUDIT_INTENTS` (audit runs deleted with their version). Config surface: `require_config(session, config, needs, *, mode)` - the single config-missing preflight (raise mode -> 422 `config_missing` with per-key settings deep-links; collect mode -> `IssueOut` blockers the run preflight converges on); `_get_or_create_agent_config` seeds the metamodel catalog/warehouse and the default source repo on ROW CREATION.
- `routes/_dev_fixtures.py` — Dev-only seed routes.

## Models

- `models.py` — Pydantic In/Out models, Intent + RunStatus + DeploymentStatus + ModelStatus enums, RunArtifactOut, AgentConfigIn/Out.
- `db_models.py` - SQLModel tables: Business, AgentConfig, Run, RunOperation, ModelVersion, Domain, Product, Attribute, FK, ProgressEvent, RunArtifact, DiagramLayout; Vibe Inputs: VibeInput (+ nullable `category` agent classification), VibeInputContextLink, RunInputLink, RunNextVibeLink, Subdomain, ProductReview, RunElementLineage (+ `previous_element_id` lineage / `Product.subdomain_id`).

## Dispatch + state

- `job_launcher.py` — Session-ID gen + bigint conversion, widget assembly, persistent agent job create/reset (`max_concurrent_runs` from AgentConfig), `launch_run`.
- `run_state_transitions.py` — `transition_run`, terminal-message composition (failed/cancelled/rolled-back/completed), atomic Run + RunOperation status propagation.
- `run_version_semantics.py` — Intent → version-metadata semantics (model-producing vs lifecycle intents).
- `progress_tracker.py` - Per-run async Delta + Jobs API polling, progress event sync, mirror to Lakebase, post-completion model sync; reads `_metamodel` catalog from AgentConfig; `_finalize_run_inputs` atomically flips `VibeInput.consumed` for the run's `RunInputLink`s in the same commit as the terminal run-status transition.
- `progress_schema.py` — Pydantic shapes for progress events.

## Services

- `services/operations/{install, uninstall, vibe_iterate, shrink_to_mvm, enlarge_to_ecm, generate_ecm, generate_samples, import_from_volume, snapshot_version}.py` — Per-primitive Operation class (dispatch / observe / rollback).
- `services/operations/{_protocol, _registry, _generation_common}.py` — Operation interface + registry + shared generation helpers.
- `services/orchestrator/{factories, validate, dag, _runner, _types}.py` — DAG composition + validation + sequential runner.
- `services/orchestrator/dag_factories/{_simple, _unified, _vibe_new_ecm_mvm, _recovery}.py` — Intent → DAG factories.
- `services/{artifact_indexer, business_digest, import_metamodel_writer}.py` — Cross-cutting services. `artifact_indexer` owns the canonical public `walk_volume_dir` (recursive, reads `entry.name`) + `infer_artifact_type` folder-rule ladder (incl. `.txt` parent-folder typing: `vibes/*.txt`→`vibes_text`, `ontology/*.txt`→`ontology_text`).
- `services/industry_download.py` - Synchronous GitHub industry-model download → `kind='industry'` Business + draft ModelVersion + Volume materialize/index. Conflict unit is the model scope within the industry: creates the industry (`on_conflict_applied="none"`), ADDS a never-seen scope under an existing industry without mutating its row (`"added"`; request `sector_id` ignored for an existing industry), or raises 409 `industry_model_already_exists` on a same-scope clash. `DownloadResult` carries `domains`/`products`/`attribute_count`/`fk_count` straight off the same `ImportAnalysis` used to unwrap the model.json, feeding the FE completion dialog.
- `services/github_publish.py` — `publish_model_version`: publishes a version's bundle to GitHub as one PR via the OBO `UserClient` + UC HTTP connection (`serving_endpoints.http_request`, ENUM method, `json` as string). Consumes `model_export.iter_bundle_files` (same tree as the zip); guards 422 `github_connection_missing` (no OAuth U2M UC connection — the human-gated step) / `github_pat_not_implemented` (deferred). Records an audit `Run`.
- `services/industry_kickstart.py` — `kickstart_from_industry`: clone a `kind='industry'` version into a fresh `kind='business'` business (structure via export→sync round-trip, Volume artifact copy + index, provenance columns, audit Run). Structure-only fidelity gap documented in the module docstring.

## Sync + read paths

- `model_sync.py` — model.json → Lakebase (Domain/Product/Attribute/FK), Delta `_metamodel.*` writes + reads; threads `run_id` → `_link_previous_version` lineage pass (synchronous final drain on Session-Ended, then `model_lineage`). Structured next-vibes ingestion (ADR D-044/D-045) is the SINGLE producer of `VibeInput(agent_next_vibe)` rows: `_capture_run_metadata` (threaded `run_id`) loads the next-vibes artifact `(payload, path)`, `_parse_next_vibes_findings` classifies `next_vibes.txt` into per-finding category/severity/target/Quality Score (`_next_vibes_payload_from_txt` builds the structured payload directly, no blob), `materialize_next_vibe_inputs` writes anchored rows at sync time (idempotent uuid5, shared `anchor_resolve` resolver), and `register_next_vibes_artifact` registers the raw txt as a `RunArtifact`. The legacy `next_vibes_json` blob is retired (dropped in `v_0_6_4`).
- `model_export.py` — inverse of `model_sync.sync_from_model_json`: reads a version's Lakebase Domain/Product/Attribute rows via a Session and reconstructs the agent-envelope `model.json` (`export_model_json`); `bundle_layout`/`BundleLayout` is the single code-level on-disk layout descriptor (`<industry>/<scope>_vN/`); `iter_bundle_files` is the single source of truth for a bundle's contents (model.json + companion artifacts, with collision dedupe), consumed by both `build_bundle_zip_bytes` (the downloadable zip) and `services/github_publish.py` (the published tree) so the two can't diverge. Surfaced by the read-only `exportModelJson` / `exportModelBundle` routes.
- `model_lineage.py` — rename/merge/delete lineage resolver: reads `RunProgressEvent` signals, sets `previous_element_id` pointers (exact/rename tiers), writes `RunElementLineage` merge/delete/rename rows, upserts subdomains (uuid5 natural key converging with Task 3).
- `explorer.py` — Lakebase-first model explorer with Volume JSON fallback (`_read_volume_json` shared by `_load_model` + `_load_model_json_envelope`); in-memory cache invalidation; product-canonical review reads (`listProductReviews` effective per-product states, `getReviewProgress` rollup) + `ModelSummaryOut.review_pct` via `review.compute_progress`; next_vibes metrics reads (`getNextVibeMetrics` model scope, `getDomainNextVibeMetrics` domain scope) via `next_vibe_metrics`; evolution metrics read (`getEvolutionMetrics`, model scope) via `evolution_metrics` off the raw Volume `model.json` envelope.
- `review.py` — product-canonical review spine (ADR D-044): the computed default-state rule (`no_review_needed` iff unchanged + no open issues, else `not_reviewed`; base version has no predecessor → nothing auto-`no_review_needed`), effective-state resolution over the sparse `product_reviews` rows + the change diff + the (degrading) open-issue gate (agent-origin anchored VibeInputs), and the product-level progress measure + per-domain rollup.
- `next_vibe_metrics.py` — next_vibes "expected work" metrics (T13, ADR D-044): aggregates the open (active, non-consumed) `agent_next_vibe` VibeInput backlog anchored to a version into the Model Quality Score (mean of in-scope `confidence_score`), per-`NextVibeCategory` open counts, and `total_open`. Model scope = any anchor; domain scope resolves anchors via direct `domain_id` or the product → domain map. Reuses `review`'s origin/status string literals so the two open-input readers can't drift; degrades to zeros/null + `has_data=False` pre-ingestion.
- `evolution_metrics.py` — model evolution metrics (T16, "Model Evolution Metrics" epic): pure projection of the agent's `_vibe_session_metadata` (read on demand from the version's Volume `model.json` envelope by `explorer._load_model_json_envelope`, NOT Lakebase — the sync drops it; no migration) onto size / quality / change / effort / provenance areas. Data-driven degradation flags: `has_metadata` (False for pre-metadata imports → size from structure fallback), `has_confidence` (False for ECM/unjudged → confidence null, never 0), `has_predecessor` (False on baseline → change deltas null, trend `"baseline"`; derived from `version_trend`/history, not the unreliable `previous_version`).
- `report_export.py` — Statistics-report Excel export builder (T15, story "Export the statistics report"): pure `build_report_workbook(ReportData) -> bytes` via `xlsxwriter` from scratch (no app state, no DB). Workbook mirrors the scope tree — `Model` (visible landing: header + the four areas + Where-to-focus ranked table with autofilter + Focus data bars + per-row drill hyperlinks) → hidden `Data` sheet feeding NATIVE recomputing charts (never images) → one tab per domain (+ back-to-Model link). `sanitize_sheet_names` enforces Excel's <=31-char / forbidden-char rule and de-dupes after truncation; `internal:` link targets reuse the same sanitized name. Baseline/ECM → `"n/a"` literal + omitted chart (no broken placeholder). Assembled + streamed by `explorer.getStatisticsReportXlsx`.
- `_compile.py` — `compile_inputs`: shared read-only serializer turning selected VibeInputs into one markdown doc + provenance blocks (replaces the `_merge_*` helpers). Long/rich inputs (`_is_rich`: newline OR len>150) render as blank-fenced markdown blocks preserving their own newlines/markdown (`_block_body` strip pair); short inputs stay one-line bullets. Byte-identical to the FE `compilePreviewMarkdown` via `tests/fixtures/compile_blocks_fixture.json` (Task 10).
- `_relink.py` — `relink_input`: re-link tier resolver carrying a VibeInput's anchor forward to a version via `previous_element_id` (auto) + `RunElementLineage` merges (review) + ancestor fallback (review) + tier-5 system-deprecate.
- `diagram.py` — ER layout (ELK + JS bundle `elk.bundled.js`, `elk_layout.cjs`).
- `import_model.py` — model.json import parser/validator.
- `subdomain_allocation_parser.py` + `version_resolution_parser.py` — Observe-time parsers for in-flight ModelVersion fields.
- `industry_catalog.py` — Reference industry catalogs + seed paths.
- `initial_sync.py` — App bootstrap sync.
- `deployment_verifier.py` — Catalog-vs-Lakebase drift probe.
- `oob_detector.py` — Out-of-band model change detection.

## Sources (external catalog seam)

- `sources/base.py` — `SourceConnector` ABC + value types (Wave 1 Track C): browse (`list_sectors`/`list_industries`/`list_models`) + fetch (`fetch_model_json`/`fetch_artifacts`) + `capabilities()` self-description. Capabilities carry the three axes — `TargetKind` (element kinds the source provides), `DiscoveryMode`, `MaterializationTiming` — plus `provides_sectors`. Error types: `SourceError` base, `SourceNotFoundError` (404), `SourceRateLimitError` (429), `SourcePermissionError` (401/403 access denial → HTTP 403). Source-agnostic so a future lakehouse/Volume source slots in behind the same ABC (no source registry).
- `sources/github.py` - `GithubSourceConnector` + `build_github_connector` (+ `GithubAppTransport`/`GithubAppCredentials`; `UcConnectionTransport` retained for the future publish path). Read-only repo browse via the GitHub contents API + `raw.githubusercontent`. Read-transport precedence: explicit `http=` override > `app_credentials` (deployment-wide GitHub App from `AppConfig`) > anonymous `requests`. With App creds, `GithubAppTransport` signs an RS256 JWT (pyjwt), mints a 1h installation token (module-level cached, refresh at expires_at-300s or on 401), calls `api.github.com` with `Authorization: Bearer <token>` at 5,000 req/hr (immune to the industry repo's SAML SSO), and routes file reads through the Contents API with `application/vnd.github.raw+json` via the shared `_translate_github_url` rewrite; `capabilities().auth_mode` is `github_app`. No App creds → anonymous (60 req/hr), `auth_mode=anonymous`. The per-user `oauth_u2m` UC connection is NO LONGER selected for reads (EMU/SAML-blocked on the test workspace). Flat repo (industries at root, no sector level) → one synthetic sector; default repo from `agent_config` when set. `fetch_readme` (scope readme, version-readme fallback, `None` on both-missing) + `fetch_releasenotes` (best-effort, `None` on any failure) + module-level `parse_model_statistics` (parses a release-notes "MODEL STATISTICS" block by label, never by line order; all-null on an absent/unparseable block) back the preview's README + domain-statistics fields.

## Core + config

- `core/dependencies.py` — `Dependencies.{Client, UserClient, OptionalUserClient, Config, Session, Tracker, BusinessAdminOnly, AdminOnly}` DI. `OptionalUserClient` yields the OBO client when an `X-Forwarded-Access-Token` is present, else `None` (read-only endpoints that degrade to anonymous instead of 500-ing).
- `core/_config.py` — `AppConfig` from environment.
- `core/lakebase.py` — Lakebase engine + session factory; `_add_missing_columns()` lightweight migrator (mirrors `scripts/db/migrate.py`).
- `core/anchor_resolve.py`  -  Shared name-context→element-FK anchor resolver (`_resolve_anchor` + `_parse_edge_id`) scoped to a supplied version; used by the live Add-Feedback capture path (`create_vibe_input` with `origin_context`) and `_compile`. Also home to the natural-key re-anchor helpers (`capture_named_anchor` / `resolve_named_anchor`, subdomain + attribute aware) shared by the kickstart clone and force-resync (`model_sync._delete_existing`) paths.
- `core/_tracker.py` — Background poller orchestration + resume.
- `core/_catalogs.py` - The single resolver per catalog-shaped concern: `resolve_metamodel_catalog` (A, installation `_metamodel` catalog = `AgentConfig.deployment_catalog`, exposed as `metamodel_catalog`), `resolve_run_target_catalog` (C, a run's `deployment_catalog` widget, defaulting to A), `resolve_version_volume_catalog` (per-version artifact volume = `mv.uc_catalog` else A). Concern B (install catalog) has no resolver by design. Cross-concern inline `x or y` fallbacks are banned and drift-locked by `tests/test_app/test_catalog_drift_lock.py`.
- `core/{_names, _paths, _widgets, _ids, _roles, _sql, _warehouse, _headers, _request_id, _static, _defaults, _factory, _base, _bundled_agent_init}.py` — Naming, paths, widgets, IDs, roles, SQL, warehouse, headers, request IDs, static files, defaults.

## Migrations

- `migrations/registry.py` — `reconcile_schema()` + `_drop_public_schema()` (gated by `PRE_PROD_DESTRUCTIVE_RESET`).
- `migrations/v_0_*.py`  -  Versioned migrations; latest = `v_0_7_0`: adds nullable `model_versions.agent_version` (agent-logic counter `4.x.y`) + `model_versions.release_version` (public/compat release identity `0.8.0`), populated at sync/import from the model.json envelope via `agent_compat.extract_version_provenance` (pre-existing rows stay NULL). `v_0_6_6`: DB-level delete integrity + legacy feedback retirement + search trigram indexes. Holds `FK_RULES` (the single source of truth for per-FK ON DELETE actions, 28 CASCADE + 9 SET NULL; `db_models` `ondelete=` and `scripts/db/migrate.py` both pair against it), drops `feedback`/`run_feedback_links`/`backfill_status`, and (Postgres only, best-effort, savepoint-isolated) creates `pg_trgm` GIN indexes on `attributes.name`/`attributes.column_name` (`TRGM_INDEX_COLUMNS`) backing `searchModelElements`'s attribute-name ILIKE filter. `v_0_6_4` is the Industry Management spine (creates `sectors`; adds `businesses.kind`/`sector_id`/`source_industry_id`/`source_version`; `agent_config` GitHub config columns; ADR D-046..D-050) PLUS the subtractive drop of the retired `model_versions.next_vibes_json` blob (structured `VibeInput(agent_next_vibe)` rows replace it). `v_0_6_3`: review-state spine (`product_reviews`, drops `domain_reviews`; ADR D-044) + nullable `vibe_inputs.category`. `v_0_6_2` is the SINGLE feature migration for the whole Vibe Inputs redesign (creates `vibe_inputs`, `vibe_input_context_links`, `run_input_links`, `subdomains`, `domain_reviews`, `run_element_lineage`, `backfill_status` plus the `previous_element_id` lineage columns and `products.subdomain_id`).
