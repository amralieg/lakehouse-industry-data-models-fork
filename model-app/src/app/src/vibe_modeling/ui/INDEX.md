# Frontend index

React + Vite app under `src/app/src/vibe_modeling/ui/`. TanStack Router (file-based), shadcn/ui, Orval-generated API client, Tailwind v4. One line per file/dir; keep current-state only when adding/moving/removing.

## Routes (TanStack file-based)

- `routes/__root.tsx` — Top-level layout (ThemeProvider, Toaster, Outlet).
- `routes/route.tsx` — Authenticated `_sidebar` layout shell + navigation.
- `routes/_sidebar/index.tsx` — Landing redirect.
- `routes/_sidebar/profile.tsx` — Profile + role view.
- `routes/_sidebar/settings.tsx` - Settings: five URL-backed tabs (`?tab=`): **agent** (notebook path, runtime concurrency/statistics), **platform** (metamodel-catalog card wired to get/setMetamodelCatalog with inline `^[a-z][a-z0-9_]+$` validation + SQL warehouse), **sources** (`GithubConfigSection` repo owner/name + auth mode + UC connection name, plus the anonymous-mode rate-limit banner driven by `getSourceCapabilities.auth_mode`), **sectors** (CRUD), **preferences** (per-user diagram column-mode defaults + reset-to-defaults). `validateSearch` redirects legacy deep-links `diagram`->`preferences`, `warehouse`->`platform`, `github`->`sources`.
- (The source explorer is no longer a standalone route. It is hosted in `components/source-explorer/source-explorer-dialog.tsx`, launched from the Industries page "Download from source" button.)
- `routes/_sidebar/businesses.{index, new, tsx}.tsx` — Business list + creation.
- `routes/_sidebar/businesses.$businessId.{tsx, index, edit, explorer, runs}.tsx` — Per-business shell, redirect, edit, model explorer (with friendly 404), runs list. The explorer header carries a "Kickstart a business" action (gated on `kind === "industry"`, opens `KickstartDialog`) and a "Kickstarted from <industry> v<n>" provenance line for kickstarted businesses (`source_industry_id`).
- `routes/_sidebar/businesses.$businessId.runs.{new, $runId}.tsx` — New Run form (dispatches exactly the server-persisted `selected_for_run` set; shows a read-only scrollable compiled-instructions preview of that set + the per-run instructions editor + an "Edit inputs →" back-link to Compose), run-detail page with cancel dialog.
- `routes/_sidebar/businesses.$businessId.model.$version.$scope.{tsx, index, $domainName.*}.tsx` — Model version pages: overview, per-domain, per-product.
- `routes/_sidebar/businesses.$businessId.model.$version.$scope.inputs.{tsx, index, $inputId}.tsx` — Vibe Inputs compose surface (ComposeSurface) + card-details page (metadata/instruction over the scoped ModelView viz tabs).

## Components (by feature)

- `components/ui/*.tsx` — shadcn primitives (button, input, card, dialog, select, table, tabs, popover, sidebar, command, alert-dialog, sheet, tooltip, tag-input, sortable-table-head, textarea, checkbox, badge, alert, avatar, markdown-toolbar, progress, separator, skeleton).
- `components/apx/` — Theme provider, app-shell helpers.
- `components/runs/` — New Run form, launch dialog, deployment catalog picker, what-you-submitted summary.
- `components/overview/` — Model-version overview tab band (Model Evolution Metrics). `metrics.ts` — pure `deriveOverviewMetrics(model, {feedbackCount, runsCount, evolution, nextVibe})` → the four areas (Change / Quality / Review / Size+effort) plus `confidenceDeltaTone` (±5-point colour rule). Evolution (T16) backs confidence + delta + version sparkline, open-issue severity split, Δ-open-issues and tokens/hours effort; next-vibe (T13) backs the Quality Score. The "uncomputable → `??`" rules are flag-driven: ECM (`has_confidence` false) has no confidence/issues/sparkline; a base version (`has_predecessor` false) has no delta/sparkline/Δ-issues; `% touched` stays `??` (no per-product diff on the wire); effort degrades when evolution recorded none. `metrics-band.tsx` — `MetricsBand`, Direction A insight-strip render (4-cell hairline-divided scoreboard: hero + supporting per area, inline SVG `Sparkline`, `DeltaChip` colour rules, severity split, `??` tooltip placeholders, action links into Feedback). `command-strip.tsx` — `CommandStrip`, the compact bordered action row replacing the old Actions + Runs cards (Install/Uninstall/Generate samples/Re-sync + ECM-only Vibe ECM + MVM launcher, with run-status summary + Installed badge). `publish-version-dialog.tsx` — `PublishVersionDialog`, the "Publish to GitHub" command-strip action: opens a PR for the version's artifacts via `usePublishModelVersion`; pre-checks `useGetGithubConfig` (non-suspense) and disables the trigger with a `/settings?tab=github` tooltip link when `connection_name` is empty; degrades a 422 (`github_connection_missing` / `github_pat_not_implemented`) into the same Settings link inline; renders the resulting PR number/url/branch/files on success.
- `components/artifacts/` — Artifacts tab + per-artifact preview/download (business-scoped).
- `components/business/` — Business CRUD widgets, sector selector (`sector-select.tsx`).
- `components/explorer/` — Model explorer tree + drill-in.
- `components/source-explorer/` - Source-browse surfaces: `source-explorer-dialog.tsx` (`SourceExplorerDialog` - large modal hosting the explorer composition + its `SourceExplorerError` boundary, launched from the Industries page; builds a `downloadedScopesByIndustry: Map<industryNameLower, Set<scopeLower>>` off `kind='industry'` businesses' `downloaded_scopes` for per-(industry, scope) "already downloaded" badges; owns the `DownloadCompleteDialog` state + the "View industry" navigate), `source-capability-banner.tsx` (source-kind info line + Settings link), `source-tree.tsx` (folder-faithful Industry → Version → Scope browse - the synthetic sector tier hides when `capabilities.provides_sectors===false`, reading the sector id off the fetched `sectors[0]`; resolves a local-sector hint by display-name match; emits a `SourceTreeSelection` carrying the source industry name + leaf scope; renders a "Downloaded" badge per scope leaf keyed on `downloadedScopesByIndustry`), `source-model-preview.tsx` (header renders scope/version VERBATIM off the folder path; body renders the model's README via `MarkdownView` (empty-state when null) + a best-effort domain-statistics row (hidden when every stat is null); Download/`Download again` affordance producing a `SourceModelSelection`, with an "already downloaded" note when `alreadyDownloaded`), `artifact-catalog-panel.tsx` (catalog rendered purely off `ModelPreviewOut.artifacts` - found / not-found-locate / tier-unavailable; DISTINCT from `components/artifacts/`), `download-complete-dialog.tsx` (`DownloadCompleteDialog` - the download-finished notification: summarizes business name/scope/version/domains/products/attribute+FK counts sourced from the download's own result, surfaces warnings inline, offers "View industry" / "Download another scope").
- `components/diagram/` — ER diagram canvas + interaction. `diagram-colors.ts` resolves the `--diagram-*` CSS palette off the document root at runtime (memoized) and exposes hex + derived-rgba fills for the SVG/canvas layers, with `globals.css`-identical fallbacks for jsdom.
- `components/feedback/` — Add-Feedback button + capture dialog (creates a first-class VibeInput via `createVibeInput`, origin=user, with a priority control; anchor resolved server-side from the view context) + feedback list.
- `components/next-vibes/` — Next-vibes card.
- `components/import/` - Import-new-business dialog. `download-industry-dialog.tsx` - `DownloadIndustryDialog`: materializes a source `SourceModelSelection` into a `kind="industry"` business via `useDownloadIndustryModel` (target sector via `SectorSelect`, pre-filled from `suggested_sector_id`; sector is ignored server-side when the industry already exists). The conflict unit is the model SCOPE within the industry: the single submit (no `on_conflict`) creates the industry, ADDS a never-seen scope under an existing one, or 409s on a same-scope clash. On success: invalidates businesses/sectors, closes itself (`onOpenChange(false)`), and hands the result to `onDownloaded` - no toast; the host's `DownloadCompleteDialog` is the notification. Mounted (stacked) from `components/source-explorer/source-explorer-dialog.tsx`. `download-conflict-step.tsx` - `DownloadConflictStep` + `parseDownloadConflict` (delegates to the shared `parse409` in `lib/api-error.ts`): on 409 `industry_model_already_exists` renders a button-free "already downloaded - delete in-app to re-pull" notice (additive semantics block same-scope outright; no Replace / Create-distinct).
- `components/industry/` — Industry-specific dialogs. `kickstart-dialog.tsx` — `KickstartDialog`: kickstart a new business from an industry's published model version (Story 8, ADR D-046/D-048). Collects required `new_name`, optional `new_description`, and a `source_version` picker (the industry's own versions via `useGetExplorerVersions`, data under `result.data`); whole-model only (`whole_model: true`, no scope narrowing). On success navigates to the new business explorer + invalidates `listBusinessesKey()`; 409 (`business_name_taken`) → inline name error, 404 → "version no longer exists".
- `components/versions/` — Version nav + history.
- `components/lineage/` — Lineage visualization.
- `components/settings/` — Settings page sections (incl. Concurrent runs input).
- `components/backgrounds/` — Background task status display.
- `components/statistics/` — Statistics tab (Model Evolution Metrics). `statistics-tab.tsx` — shell: a persistent two-level scope tree (Model + one leaf per live domain) left, a report pane right that rebinds to the selected scope (single `scope` state, model view ⇄ domain view, sticky scope-header + "Back to model"); derives degradation flags (`hasConfidence` from scope≠ECM, `hasPredecessor`). `scope-tree.tsx` — the tree + `Scope` type. `report-sections.tsx` — `ModelReport`/`DomainReport` section placeholders in documented order with Skeleton/"coming soon" bodies; `TODO(T6/T7)` stubs for the real metric/data binding. `no-data.tsx` — the quiet `n/a` degradation token (slash icon + tooltip).
- `components/review/` — Review-marking UI (T4, ADR D-044). `review-state-control.tsx` — reusable three-state control: product marks directly (Reviewed → `markProductReview`; Not reviewed → `clearProductReview` to revert an explicit mark, else upsert a `not_reviewed` override over the computed default), domain/subdomain route through the cascade dialog and only call the cascade endpoint on confirm; `no_review_needed` renders a read-only muted badge but stays overridable; invalidates progress + product-review queries on success. `cascade-confirm-dialog.tsx` — AlertDialog gate surfacing the scope ("this will mark N items") + are-you-sure; `onConfirm` fires only on confirm, never cancel/dismiss. `review-progress.tsx` — Suspense indicator off `getReviewProgress` (reviewed ÷ review-needed; `no_review_needed` excluded; "nothing to review" empty state). `review-state-labels.ts` — canonical state label + badge-token helpers (reuses success/warning/muted; no new colors). Wired into the Statistics tab — per-product `ReviewStateControl` lives in the domain breakdown; `review-progress.tsx` backs the report sections and the Overview metrics band's review cell.
- `components/vibe-inputs/` — Vibe Inputs compose surface (Concept A). `model-view.tsx` — reusable model-visualization tab host (diagram/relationships/ontology/artifacts/feedback/statistics; the statistics tab body is supplied via `statisticsSlot` by the model route), shared by the model route and the input card-details page. `state.ts` — `deriveInputState` (deprecated>needs_link_review>consumed>active) + anchor mappers (`anchorFromInput`, `anchorPathForCompile`, `isIncludedInCompile`), the single source of truth for input state across card/details/filters/review. `compiled-preview.tsx` — read-only compiled-instructions pane consuming the byte-parity `lib/instructions.compilePreviewMarkdown`. `input-markdown-editor-dialog.tsx` — modal wrapping the real `ui/markdown-editor.tsx`, ⌘↵-saves durably via `useUpdateVibeInput`. `query-keys.ts` — `invalidateVibeInputQueries` predicate (one invalidation set for all input mutations). `chips.tsx` — OriginBadge (defensive on unknown import origins) / PriorityIndicator (Task 11 enum, token-tinted flag) / StateChip / ReviewChipButton. `vibe-input-card.tsx` — the editable card: a server-backed `selected_for_run` selection toggle, meta chips, inline click-to-edit short text vs clamped rich-markdown preview opening the editor. `following-pane.tsx` — model-subgraph pane following the focused card; reuses the real DiagramViewer scoped to the card's domain, lazy + never all-domains (ELK perf), empty state for model-wide. `section-tree-model.ts` — `buildSectionTree` (groups inputs by hydrated anchor path, only branches-with-inputs + Model-wide, per-node anchor ids for create). `section-tree.tsx` — recursive collapsible tree of cards + inline add-instruction composer + expand/collapse all + filter force-expand + a per-node "Select all under this branch" control (collects the subtree's selectable input ids → `setVibeInputSelection`, with none/some/all node state). `filters-bar.tsx` — search + origin/state/priority/selected selects (the Selected filter = Selected / Not selected / All) + shown/total count + `filtersToQueryParams` (state→status/consumed/needs_link_review server params). `review-queue-dialog.tsx` — resumable (localStorage cursor, clamped to live queue) one-at-a-time link review modal; Accept/Re-anchor(ModelElementPicker)/Dismiss via the review hooks; two-entity RelationshipAnchor for fk items. `compose-surface.tsx` — Concept-A two-column assembly: filters + section tree (left), segmented compiled-preview/following-pane (right), review banner+dialog, editor dialog, focused-card tracking. The server-backed `selected_for_run` set (read from `VibeInputOut`, toggled via `setVibeInputSelection` with optimistic update) is the single source of truth for the count, the Selected filter, and the compiled preview; a "Start run · {N} selected →" header CTA (disabled at N=0) navigates to the New Run route, which reads the persisted selection.

## Lib

- `lib/api.ts` — Orval-generated OpenAPI client + hooks (do NOT edit manually; regenerates from backend OpenAPI).
- `lib/api-error.ts` — `ApiError` discriminator + helpers: `apiErrorMessage` (toast-friendly message extraction) and `parse409<T>(err, errorLiteral)` (the shared 409-conflict-envelope parser — unwraps the body or `detail`, checks the `error` discriminator; used by both `parseConflict` in import-new-business-dialog and `parseDownloadConflict`).
- `lib/selector.ts` — Default query selector (`useSuspenseQuery({ ...selector() })`).
- `lib/hooks.ts` — Shared React hooks (toast, route helpers, `useDebouncedValue`).
- `lib/business-cache.ts` — `invalidateBusinessLists(queryClient)`: invalidates ALL `/api/businesses` list queries (unfiltered + kind-filtered) via a queryKey-prefix predicate, so the kind-filtered Industries list refreshes after download/kickstart/create/edit/delete (the bare `listBusinessesKey()` misses the `{kind}` key).
- `lib/retry-transient.ts` — `retryOnTransientGateway()` / `isTransientGatewayError()`: bounded auto-retry (linear backoff) for POSTs that hit a transient edge-proxy 502/503/504; retries clear-on-retry gateway hiccups (E-04, kickstart) while rethrowing 4xx / app-500 unretried. `onTransientError` fires per occurrence (retried or exhausted) for logging.
- `lib/client-telemetry.ts` — `reportClientGatewayError()`: records a browser-observed transient gateway error in BOTH the console and the app logs (fire-and-forget beacon to `POST /api/client-telemetry/gateway-error`), so an E-04-style 502 stays diagnosable in `databricks apps logs` even when a client retry recovers it.
- `lib/run-form.ts` — Run-form blocker derivation.
- `lib/intent.ts` — Intent ↔ run-type conversions, label maps.
- `lib/instructions.ts` — `compilePreviewMarkdown` / `compileInputBlock` / `isRichText` — the FE twin of the backend `compile_inputs`, byte-identical via `tests/fixtures/compile_blocks_fixture.json` (Task 10).
- `lib/operations.ts` — RunOperation status helpers.
- `lib/diagram-layout.ts` — Layout normalization.
- `lib/date.ts` — Tz-aware datetime formatting (`formatDate`/`formatDateTime`/`formatRelative` "time ago"/`formatElapsedSeconds`/`formatDuration`).
- `lib/industry.ts` — `industryDisplayName()` render-time resolver (slug→catalog display name, else title-case).
- `lib/sector.ts` — `sectorDisplayName()` render-time resolver (Business.sector_id → Sector name; null for unset/dangling).
- `lib/entity-kind.ts` — `entityKindLabel()`/`entityKindLabelLower()` — the single source of truth for the Business vs Industry noun off the `businesses.kind` discriminator (ADR D-046).
- `lib/source-selection.ts` — `SourceModelSelection` contract between source-explorer (Track A) and download-dialog (Track B); shared type stub for Wave 2 FE Tier-0.
- `lib/utils.ts` — `cn()` etc.
